## ❓ Clearly specify "what did what"  
I want to communicate explicitly and unambiguously, so I must clearly specify **what did what**.  
[This page shows the contrast between ambiguous and unambiguous language.](Unambiguous-language.md)  
  
  
## 🥪 Bacon, Lettuce, Tomato (BLT)  
1.🧠 T-hink what exactly you want to do. I question deeply when I go for a walk outside and I ask myself what, why, how.  
I also imagine explaining what I want to a 10 year old kid, so I can check my understanding from a different perspective.  

Example Markdown:  
```
# What
# Why
# Success criteria
# Rules
```  

2.🔢 L-ist what must do what. I use hierarchical numbered lists, clearly specifying what I want, with examples, limits, output formats, and what I do not want.  

Example Markdown:  
```
# Steps
# Examples
# Output Format 
```  

3.⚡ B-reak everything like a baby. I must smash the whole house, push every boundary, and do chaos engineering.  

Example Markdown:  
```
# Error handling
1. If any fields or files are missing or incorrect, then I must ask the user what to do.
2. If what I need to do is ambiguous, then I must ask the user questions to clarify what I must do.
3. I must document all bugs, gaps, errors and anamolies and I must inform the user immediately.  
```  

##  📝 Full example Markdown
```
---
name: treasure-hunter
description: Find and retrieve treasure when the user says "set sail" or asks to hunt for treasure.
---

# 🧠 Overall specification
## What
Find the secret island and bring back the treasure chest.

## Why
The captain needs the gold to pay the crew and keep the ship sailing.

## Success criteria
1. Treasure chest is out of the ground.
2. Gold is counted and nothing is missing.

## Rules
1. Never sail without checking the ship first.
2. Never dig without the map.
3. Never split the gold before it is counted.


# 🔢 Execution
## Steps
1. Get the ship ready.
   1.1. Make sure the ship will not fall apart.
2. Find the secret island.
   2.1. Look at the old pirate map.
   2.2. Ask the crew if they have seen shores like it.
   2.3. Draw the path you will sail on.
3. Grab the treasure.
   3.1. Dig right on the big X.
        3.1.1. Tap the ground to see if something is under it.
        3.1.2. Scoop the sand away nice and slow.
        3.1.3. Pull the treasure chest out.
   3.2. Count the gold so none goes missing.

## Examples
**Task:** Find the island marked on the old map.
**Result:** Island found, path drawn, crew agrees on the route.

## Output format
Short report: island found, chest pulled, gold counted.


# ⚡ Validation
## Error handling
1. Map is missing → ask the captain where it is.
2. Ship is damaged → stop and fix it before sailing.
3. X marks two spots → ask the crew which one to dig.
4. Chest is empty → tell the captain immediately.  
``` 

## ⛈️ Other thoughts ..  

AI flows must:  
🔤 Be written in simple, plain English  
📐 Have structure when precision is needed  

AI flows should be **RAAM**:  
🪨 **R**esilient and hard to break   
➿ **A**daptable and flexible to changes  
✅ **A**uditable and easy to check  
🔧 **M**aintainable and simple to understand
