# ✨ AI learning
This documents my learning, approach and testing for AI. 

## ❓ Clearly specify "who or what did what"  
I want to communicate explicitly and unambiguously, so I clearly specify **who or what did what**. 

## Bacon, Lettuce, Tomato (BLT)  
1.🧠 T-hink what exactly you want to do. I question deeply when I go for a walk outside and I ask myself what, why, how. I also imagine explaining what I want to a 10 year old kid so I can check my understanding from a different perspective.  

Example Markdown:  
```
# What
# Why
# Success criteria
# Rules
```  

2.🔢 L-ist what must do what. I use hierarchical numbered lists, clearly specifying what I want, with examples, limits, output formats, and what I do not want.  

Example Markdown:  
```
# Steps
# Examples
# Output Format 
```  

3.⚡ B-reak everything like a baby. I must smash the whole house, push every boundary, and do chaos engineering.  

Example Markdown:  
```
# Errors handling
1. If any fields or files are missing or incorrect, then I must ask the user what to do.
2. If what I need to do is ambiguous, then I must ask the user questions to clarify what I must do.
3. I must document all bugs, gaps, errors and anamolies and I must inform the user immediately.  
```  


## ⛈️ Other thoughts ..  

AI flows must:  
🔤 Be written in simple, plain English  
📐 Have structure when precision is needed  

AI flows should be **RAAM**:  
🪨 **R**esilient and hard to break   
➿ **A**daptable and flexible to changes  
✅ **A**uditable and easy to check  
🔧 **M**aintainable and simple to understand
